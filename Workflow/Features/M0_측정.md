# M0 규칙 수선과 측정

2026-10-21 개발 순서의 M0-1~0-4를 기존 `SampleScene`에 적용했습니다. M0-5의 합격 판정과 수치 조정은 사람 측정 대기입니다. 자동 시험의 결과는 [실행 기록](../Tasks/m0-rules-measurement/결과.md)에 구분해 남깁니다.

2026-10-22 후속 변경: [M1](M1_밤_뼈대.md)에서 첫 발소리 성장 감소를 0.05로 완화하고 청소기 경로를 30.673m 거실 고리로 바꿨습니다. 아래는 최초 M0 적용 당시의 기록입니다.

## 적용 범위

- 측정 판: 호기심냥만, 단계별 2/2/3/3/4마리, 미끼 내성 30초. 밤 선택은 M1 대상입니다.
- 달리기 5.5m/s, 발소리 성장은 1회 0.15 감소·최소 0.6. 소리 종류는 일반·큰 소리·잔상·미끼·공입니다. 호기심냥은 미끼 > 잔상 > 추적 > 일반/큰 소리 순서로 반응하고 공은 무시합니다.
- 대시는 출발점에 잔상 원을 남기고 0.5초간 이동 소리를 내지 않습니다. 잔상에는 발소리 성장 배율이 적용되지 않습니다. 놓침 4초는 쥐의 일반/큰 소리를 들으면 초기화됩니다.
- 미끼는 1.5초 동안 먹습니다. 유인 중·먹는 중에도 잡힙니다. 먹기 시작부터 30초 내성은 기절로 사라지지 않고 `×` 기호로 표시됩니다.
- 컵 스위치는 타격 중심에서 6m 떨어져 있습니다. E를 누른 뒤 0.5초간 멈춰야 작동하고 이동·반동으로 취소됩니다. 누르기 중 반경 3m 소리가 나며 함정 범위·연결선은 항상 표시됩니다. 피격 고양이는 기절 뒤 해당 스위치를 조사합니다.
- 청소기는 기존 주방 경로 약 33.54m를 한 바퀴 돌고 충전독에서 멈춥니다. 8초 제한과 중간 복귀를 제거했습니다. 중심이 충전독 3m 안에 있을 때에는 타격하지 않고, 한 작동에서 같은 고양이는 한 번만 맞습니다. 거실 고리 경로 교체는 M1-2 대상입니다.
- 게임 시계와 실제 진행 시간을 분리했습니다. 퇴장당 최대 체력 × 2초를 당기고 시계 옆에 `+N초`를 표시합니다. 부스러기와 단계는 게임 시계, 쿨타임·기절·내성·결과 생존 시간은 실제 진행 시간을 씁니다. 정지·성장 선택 동안 모두 멈춥니다.

`AssessmentRules.asset`에서 여섯 상수(퇴장 제한 8초, 먹기 거리 0.6m, 미끼 풀 3개, 흡수 속도 9m/s, 큰 치즈 크기 1.5배, 고양이 가속도 18m/s²)와 전역 소음 배율을 조절합니다. 전역 배율 0.65는 초기 후보입니다. 성장 전 달리기를 호기심냥이 듣는 반경은 `9 × 0.65 × 1.3 = 7.605m`, 바닥 520m² 대비 원 넓이는 약 34.94%입니다. 이는 장애물·겹침을 제외한 기하 계산이며 실제 재미의 합격 근거가 아닙니다.

## 실행과 기록

Unity 6000.6.0f1에서 `MidnightMouse/Assets/Scenes/SampleScene.unity`를 엽니다. Windows 개발 빌드는 실행 기록에 표시된 동일 빌드로 확인합니다. 기존 조작에 아래 키가 추가됩니다.

| 키 | 동작 |
|---|---|
| F1 | 게임 시계를 다음 단계 시작으로 이동 |
| F2 | 게임 시계 +30초 |
| F3 | 활성 고양이를 정상 퇴장·치즈·아침 당김 경로로 처리 |

이 키와 CSV는 에디터·개발 빌드 전용입니다. 사용한 판은 `debug_used=1`이므로 사람 측정에서 제외합니다. 일시정지·결과 화면에서는 동작하지 않습니다.

한 판당 CSV 한 행을 `Application.persistentDataPath/Measurements/m0-runs-v1.csv`에 추가합니다. Windows에서는 `%USERPROFILE%\AppData\LocalLow\<회사명>\<제품명>\Measurements` 아래입니다. 승패·제목 복귀·재시작·정상 종료 때 저장하며 강제 프로세스 종료 중인 판은 보존하지 못합니다. 기존 기록을 덮어쓰지 않습니다.

주요 열은 판 ID, 측정 구성, 시나리오, 종료 원인, 실제/게임 시간, 퇴장 수, 레벨업 수, 하나 이상의 고양이에게 추적당한 시간, 사망 원인, 디버그 사용 여부입니다. `events` 열의 사건은 `실제초|종류|상세`를 `;`로 연결합니다. `trap_hit`은 함정·작동 ID·고양이 슬롯·피격 상태·바람 여부, `trap_end`는 작동별 타격 수, `chase_end`는 고양이 슬롯·지속 시간·종료 원인을 남깁니다. 밤별 부탁·게으름냥·사냥꾼냥 항목은 해당 마일스톤에서 추가합니다.

에디터는 GameController의 `_measurementScenario`를 `loop`, `corner`, `switch`로 지정합니다. 빌드는 `--m0-scenario corner`처럼 실행 인자로 구분하며 기본값은 `loop`입니다. 배치 자동 시험은 `automated`로 기록합니다.

## M0-5 사람 측정

1. 같은 빌드에서 루프 이동, 구석 버티기, 스위치 4m 안에서 미끼/E만 쓰기 각 3판을 기록합니다. 디버그 판·중단 판·자동 시험 판은 제외합니다.
2. 구석 생존율이 루프보다 낮고, 스위치 상주의 퇴장 수가 루프보다 적으며 생존율이 루프 이하인지 확인합니다.
3. 루프 판의 중앙값으로 퇴장 4마리 이상·레벨업 5~7회를 확인합니다. 같은 고양이에게 미끼/E로 다시 맞히는 간격도 사건 시각으로 확인합니다. 30초 내성이 이 전략의 실제 성능을 보장한다고 미리 판정하지 않습니다.
4. 소음 면적 25~40% 기준을 확인합니다. 퇴장 수 ±1 또는 면적 ±5%p 경계라면 해당 묶음을 5판으로 늘립니다. 실패 시 수치 한 개만 바꿔 한 번 다시 측정하고, 계속 실패하면 기획의 대안 규칙을 검토합니다.

M1~M5, M6·모바일, 쥐·고양이 리깅은 아직 구현하지 않았습니다. M0 합격과 조정 뒤 사용자가 정한 개발 순서를 이어갑니다. 외부 테스터·모델 제작·공개는 이 기계 검증으로 대체하지 않습니다.
