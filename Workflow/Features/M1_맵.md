# M1 거실·주방 배치

`SampleScene`의 기존 모델·머티리얼·충돌체를 유지하면서 청소기 경로와 출입구를 배치했다. 씬 전체 재생성이나 아트 파일 수정은 하지 않았다. 아래 좌표는 `(x, y, z)` 월드 좌표이며 바닥의 `y`는 0이다.

| 지점 | 좌표 | 용도 |
|---|---|---|
| 거실 펫도어 입장 | `(-12, 0, 0)` | 왼쪽 벽 안쪽, `M1Layout.PetDoors[0]` |
| 주방 펫도어 입장 | `(1.7, 0, 9.1)` | 위 벽 안쪽, 조리대 왼쪽 통로, `PetDoors[1]` |
| TV장 | `(-10.2, 0.6, -4.5)` | 크기 `(1.2, 1.2, 3)`, 충돌체와 `NavMeshObstacle`로 통행 차단 |
| 충전독·청소기 스위치 | `(-8, 0, -4.5)` | 청소기 고리의 첫 지점 |
| 쥐 시작 | `(0, 0, -5.8)` | 쥐구멍 ② 앞, 기존 시작점 유지 |
| 컵 A 스위치 / 낙하 | `(-3, 0, -0.5)` / `(3, 0.05, -0.5)` | 바닥 거리 6m, 기존 위치 유지 |
| 컵 B 스위치 / 낙하 예약 | `(1, 0, 5.5)` / `(7, 0, 5.5)` | 조리대 앞 보행면, 바닥 거리 6m |
| 수면 예약 ① / ② | `(-10.8, 0, -8)` / `(8, 0, -5.5)` | 컵·청소기 위험 경계에서 2m 이상 여유 |
| 공 시작 예약 | `(0, 0, -5.7)` | 컵 A 방향의 최대 6m 직선과 스위치까지 보행 경로 검사 대상 |

청소기는 `(-8, -4.5) → (-3, -4.5) → (0.8, -4.5) → (0.8, 1) → (-5, 2.8) → (-8, 2.8) → 독` 순서로 이동한다. 여기서는 `y`를 생략했다. TV장 앞에서 중앙·쥐구멍 ② 앞·러그·소파 앞을 도는 닫힌 고리 길이는 **30.673m**이다. 기존 순찰점 중 TV장에 겹치는 `(-10, 0, -3)` 한 곳만 `(-11.8, 0, -3)`로 옮겼다.

펫도어 도형은 벽 안쪽에 붙인 임시 표시다. 고양이는 벽 안쪽 입장 좌표에서 등장하고 같은 좌표로 퇴장하므로 벽 바깥까지 이동하지 않는다. 오른쪽·앞쪽 벽의 렌더러는 숨기고 바닥 이탈 방지 충돌체는 유지했다. TV장은 저장된 이동 지도 위에 런타임 구멍을 만드는 기존 의자와 같은 `NavMeshObstacle.carving` 방식을 사용한다.

## 편집과 검사

- `M1_Layout`의 `M1Layout` 컴포넌트가 출입구·예약 자리 좌표, 거리 기준, 경로·순찰 부모를 보관한다. `PetDoors`는 읽기 전용 월드 좌표 목록이다. 좌표는 씬에 직렬화되어 실행 순서에 의존하지 않는다.
- `MidnightMouse/M1 지도 적용`은 현재 `SampleScene`의 지도 부분만 갱신하고 검사 후 저장한다. `MidnightMouse/M1 지도 검사`는 저장된 NavMesh를 임시 등록해 현재 배치를 검사한다. 기존 전체 생성기도 같은 적용·검사를 호출하지만, 이미 수정한 씬에는 전체 생성을 실행할 필요가 없다.
- 검사 1은 컵 A·B 거리, 2는 수면과 컵·청소기·공의 간격, 3은 공의 최대 거리 직선과 컵 A 스위치까지의 실제 NavMesh 보행 거리, 5는 닫힌 고리 길이와 충전독 일치, 6은 시작·출입·순찰·예약·스위치·낙하·경로점의 실제 보행면과 연결 경로를 검사한다.
- 청소기 각 구간은 `NavMesh.Raycast`와 환경 충돌체에 대한 `Physics.OverlapCapsule`을 함께 검사한다. 지점만 통과하고 구간 중간의 가구를 통과하는 배치를 허용하지 않는다. 공 직선도 실제 환경 충돌체로 검사한다.
- `M1LayoutTests`는 저장된 씬의 정상 배치·TV장 보행 차단, 경로 중간 장애물, 바닥 밖 경로점의 세 조건을 확인한다. 실제 Unity 실행 결과는 현재 작업의 검증 보고서를 따른다.

선풍기는 현재 조리대 위 아트 모델만 있고 함정 기능은 없다. 기획의 예외에 따라 검사 2의 최대 바람 부채꼴과 검사 4는 미적용이다. 수면·공·컵 B는 이번 지도 검사에 사용할 예약 좌표이며 해당 게임 기능을 구현한 것으로 표시하지 않는다. 원본 씬 정적 검사에서 새 컴포넌트 참조와 청소기 6구간의 기본 도형 충돌체 간섭은 확인했으나, 이 정적 검사는 Unity NavMesh·PlayMode·화면 검증을 대신하지 않는다.

2026-10-22 통합 PlayMode 검사에서 중앙 `x=0` 직선 구간만 NavMesh 단절로 거부됐다. 물리 장애물 검사와 양 끝점의 보행 검사는 통과했다. 중앙 두 지점을 `x=0.8`로 옮겨 기존 M0 중앙 경로 쪽으로 우회했다. 정확한 단절 경계 좌표는 첫 실패 로그에 없으므로 타일·폴리곤 경계 가능성은 가설이며, 후속 실패에는 경계 좌표와 거리를 기록한다. 이 수정의 실제 NavMesh 통과 여부는 새 고정 후보 검증으로 확인한다.
