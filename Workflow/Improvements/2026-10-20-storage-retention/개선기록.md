## 관측과 선택

2026-10-20의 파일 조사에서 검증 run 8개의 `Project/Library` 합계는 18,953,940,216바이트(17.65GiB)였다. 검증기는 소스만 복사하지만 Unity가 매번 새 캐시와 준비 빌드를 만들고, 종료 뒤 이를 남겼다. 지침도 실패 기록 보존과 모든 중간 파일 보존을 구분하지 않았다.

원인은 재귀 복사로 입증된 지수 증가가 아니라 실행별 대용량 생성물과 중간 산출물의 누적이다. 이번 변경의 기준은 [보관 규칙](../../AI_지침.md#6-보관과-정리)이다. 원본·최신 결과·필수 근거를 남기고, Git에서 복구 가능한 이전 파일은 OID와 경로로 참조한다. 단순 조회마다 별도 문서·백업을 만들지 않는다.

수동 정리만 하는 안은 이후 실행에서 같은 누적이 반복된다. `Library` 공유는 실행 격리와 캐시 유효성 문제를 추가하므로 선택하지 않았다. 기존 검증 절차는 유지하고 현재 run의 재생성 임시물만 종료 후 제거하는 안을 적용했다.

## 적용과 복구

사용자의 이번 개선 요청에 따라 다음 검증부터 적용한다. 과거 계약의 release ID와 원시 증거는 바꾸지 않는다. 활성 검증기 SHA-256은 `e31452275495df4a0307f8fe7f404e3ce2bd9b5025f24d031b5093f60646eb1a`, 검사 파일 SHA-256은 `63123a6e37ec8c6d98cd0a870e3beedceda208a42239bb4a7baff4bff2c48643`이다. 운영 파일 목록과 해시는 [workflow.lock.json](../../../workflow.lock.json)에 있다.

증거 등급은 검사한 동작에 대한 `CORRECTNESS`다. 실제 Unity 종료 후 잠금·자식 프로세스 상황은 다음 검증의 `storage_cleanup`으로 확인해야 한다. 검증 프로세스가 강제 종료되면 정리가 실행되지 않을 수 있으며, 정리 미완료는 숨기지 않는다. 저장 공간을 실제로 줄인 효과나 생산성 개선을 실측한 것으로 주장하지 않는다.

복구가 필요하면 위 Git OID에서 이번에 바꾼 운영 파일·검증기·검사·계약 양식·lock만 확인해 복원한다. 이후 사용자 변경과 게임 파일은 되돌리지 않는다. 이전 버전으로 돌아가면 실행 임시물의 자동 정리도 중단된다.

비교용 후보 사본은 활성 파일과 동일함을 확인한 뒤 정리했다. 기존 대용량 자료는 삭제하지 않았다. 별도 ZIP 백업·예약 작업·새 의존성·커밋·push는 만들지 않았다. 비용과 사람 활동 시간은 미측정이다.

### 실제 실행과 자동 정리

- 첫 실행 [20261020T065756Z-6b6118f7](../../Runs/20261020T065756Z-6b6118f7/report.json)은 제한된 환경의 라이선스·Package Manager 연결 장애로 `BLOCKED_ENV`였다. 원시 실패 기록은 보존했고 생성된 `Project/Temp`는 자동 정리됐다.
- 일반 로컬 권한으로 재실행한 [20261020T065912Z-96eec7a6](../../Runs/20261020T065912Z-96eec7a6/report.json)은 537.05초에 검사 6개 모두 `PASS`였다. EditMode 18개, PlayMode 12개를 통과했고, Windows Player가 Direct3D11에서 첫 씬 60프레임을 오류 0건으로 실행하고 정상 종료했다.
