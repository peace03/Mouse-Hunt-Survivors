# 감독형 자기개선

[원문 개선 설계서](../자기개선%20워크플로우/02_safe_self_improving_ai_workflow_v2.md)의 A부를 사용합니다. 개선의 목적은 정확한 게임 제작, 사람 시간·재작업·총비용 감소입니다. 자동 작업 생성이나 운영 지침의 무단 수정은 하지 않습니다.

## 관측에서 후보까지

1. 실행 기록에서 실패·재시도·취소·사람 활동 시간·후속 결함을 함께 읽습니다. 보통 5~10건은 병목 탐색에 쓰며 효과 입증으로 부르지 않습니다. 심각한 검증 오류는 건수를 기다리지 않고 수리합니다.
2. [개선제안](Templates/개선제안.md)에 관측 사례, 원인 가설, 반대 가설, 실패 시나리오, 개선하지 않는 대안과 작은 변경 범위를 작성합니다.
3. 기존 운영 파일·환경·해시를 보존하고 `Improvements/<id>/candidate/`에서 후보를 만듭니다. 후보 스킬을 `.agents/skills/`에 symlink로 연결하지 않습니다.
4. 바꿀 요소와 고정할 요소, 과제 계열, 비교 순서, 주 지표, 실패·누락 처리, 비용·시간 한도를 실행 전에 정합니다.
5. 관련 정상·실패·회귀 시험 후 [비교 보고서](Templates/비교보고서.md)에 기준선과 후보를 짝지어 기록합니다. 실패한 시도와 개선 작업 자체 비용도 포함합니다.

## 판정과 적용

| 증거 등급 | 주장 범위 |
|---|---|
| CORRECTNESS | 특정 명세·실패 검출·회귀에 대한 정확성 |
| PILOT | 정해진 작업군에서 제한적으로 사용할 근거 |
| CONFIRMATORY | 사전등록한 모집단·통계 계획·독립 데이터가 지지하는 효과 |

측정하지 않은 비용은 `unavailable`, 측정하지 않은 사람 시간은 미확인입니다. 품질 회귀·증거 조작·권한 위반은 도입 중지 사유입니다. 작은 관찰을 전체 생산성 개선으로 일반화하지 않습니다.

필수 테스트·합격 기준·분모·검증기 수정은 일반 최적화 후보와 분리합니다. 독립적인 기대 결과와 실패 fixture로 확인하고 기준선과 후보를 모두 새 기준으로 다시 검사합니다. 과거 실패를 소급해 PASS로 바꾸지 않습니다.

[도입·복구 기록](Templates/도입복구.md)에 정확한 후보·평가 결과 해시, 대상 작업군, 기간·작업 수, 중지 조건, 이전 버전, 이미 받은 사용자 지시를 연결합니다. 검토한 버전을 다음 작업에 적용합니다. 기존 지시가 정확한 변경을 이미 허가했으면 같은 권한을 반복해서 묻지 않습니다.

## 상태와 복구

전체 허용 전이와 guard의 원본은 설계서 S05입니다. 주요 흐름은 `DRAFT → BUILDING → FROZEN → EVALUATING → REVIEW_READY → TRIAL → ADOPTED`입니다.

- 판단할 증거가 부족하면 `HELD`. 결과를 본 뒤 같은 실험에 유리한 표본을 추가하지 않습니다.
- 후보 변경은 새 candidate ID, 계획 변경은 새 experiment ID로 기록합니다.
- 활성화 전 취소는 `CANCELLED`, 활성화 후 취소·회귀는 `ROLLING_BACK`입니다.
- 신규 후보 사용 중지 → 실제 활성 버전 확인 → 보존한 기준본 복사 → 해시·회귀·필수 시작 확인 순서로 복구합니다.
- 복구가 확인되면 `ROLLED_BACK`, 불명확하면 `MANUAL_RECOVERY`로 남깁니다. 게임 소스·사용자 커밋·세이브를 자동 reset하지 않습니다.
- 이미 종료한 채택 기록은 수정하지 않고 별도 사고·복구 기록을 연결합니다.

현재는 사람이 시작하고 검토하는 절차입니다. 별도 저장소·자동 스케줄·모델 API·자동 승격·Watchdog는 반복 손실과 운영 필요가 확인된 뒤 원문 B부에 따라 따로 구축합니다.
